# 目標到達確率最大化法（GRM: Goal-Reachability Maximization）

「星を放つ夜」CPU のための、**完全アルゴリズム的**な手番決定ロジックの仕様。

## 0. 位置づけと命名

### 0.1 なぜ「AI」でなく「アルゴリズム」か

本手法は学習（NN・棋譜模倣）も、手書きヒューリスティック評価関数（テンポ評価のような近似スコア）も用いない。
代わりに、ゲームの確率構造を直接解いて **「狙うべき発火状態の集合」への到達確率を最大化する** 決定論的プランナーである。
出力は「ある仮定（観測情報＋確率モデル）の下での最適解」であり、推測やパラメータ職人芸を含まない。この意味で狭義の AI ではないため、本書では「法／プランナー」と呼ぶ。

### 0.2 既存路線との違い

- 現状最強 `tempoFastAI`（探索 + 手書き評価関数）は、**葉（ターン終了局面）の良し悪しをヒューリスティックなスコアで近似**しており、そこが律速・天井とされてきた（`ai/README.md`）。
- GRM は、この「葉の価値」を **明示的な確率量** `f(S,V) = P(このターン V 点以上)` に置き換える。評価関数の重み調整ではなく、サブゲームを解いて確率を直接求める。

### 0.3 構造：入れ子の到達確率最大化

本手法は「ある目標集合への最大到達確率」を二段で入れ子にしたものである。

- **内側** `f(S,V)`：発火後の連鎖サブゲームで「得点 ≥ V」へ到達する確率の最大化。
- **外側** `U(S)`：非発火状態の列を遷移し、良い発火状態集合 `G` へ到達する確率の最大化。

両者とも確率的システムにおける **maximal reachability probability**（目標集合への最大到達確率）として定式化される。ただし内側 `f` は連鎖サブゲームとして後退帰納で **厳密に解ける** のに対し、外側 `U` は **相手の戦略を読まず、未来コンテキストをランダム外生モデルで期待評価する有限ホライズンの到達計画** として実装する（§6・§7）。

## 1. 前提：観測情報と確率モデル

実装・確率計算の土台。`src/ai/infoSet.ts` の観測情報集合に準拠する。

### 1.1 可視情報（手番プレイヤー視点）

- 全プレイヤーのボード（各スロットのスタックを、色も積み順も完全に）
- 場の 2 ペア（`field[0]`, `field[1]`、各 2 枚の色）
- 捨札の **色別枚数**
- 山札の **枚数**

### 1.2 不可視情報

- 山札の中身の **順序**（次に何色を引くか）のみ。

### 1.3 山札の色分布とドローのモデル化（確率の基礎）

各色は **24 枚固定**（5 色 × 24 = 120）。したがって任意時点で、色 `c` の **山札内** 枚数は

```
deckCount(c) = 24 − (全ボード上の c) − (場の c) − (捨札の c)
                  − (保留カードの c) − (連鎖中に除去済み・未処理の c)
```

で **完全に逆算できる**（捨札は別途、色別枚数が可視）。最後の項「連鎖中に除去済み・未処理」は、当ターンに発火して盤面から除かれたが、まだ捨札／プレゼントとして処理されていないカード（`combosThisTurn` / `giftQueue` 相当）を指す。`f` のサブゲーム計算中はこれらも山札に存在しないので、忘れず除外する。山札の順序のみ不可視なので、ドローは「山札の色内訳からの **非復元一様抽出（超幾何分布）**」としてモデル化する。

**実ルールに沿った場合分け**（`engine.ts: drawFromDeck` / `refillField`）：

- **山札が残っている間は山札からのみ引く**。捨札は混ざらない（＝「山札 ∪ 捨札」を一つのプールとして扱ってはならない）。確率は `deckCount(·)` の色内訳に対する超幾何。
- **山札が空になったときだけ** 捨札をリシャッフルして山札に戻す。以降のドローは、その（元・捨札の）色内訳に対する超幾何になる。1 ターンの連鎖で引く枚数は通常そこまで多くないが、境界をまたぐ場合はプールが切り替わる。
- **2 枚目が引けない場合は 1 枚ドローに縮退** する（`DRAW_FROM_DECK` で山札残り 1 枚など）。

> **帰結**：山札から 2 枚引いたときの色の組は 15 通り（5 色から重複ありで 2 枚）で、各確率は上記の超幾何から **厳密に** 定まる（ユーザー構想の「2 枚の得方は 15 通り・同様に確からしくない」の数学的実体）。場のペアを取る場合は色が確定（確率 1）。

## 2. 状態 S の定義

### 2.1 構成要素

状態 `S = (s, t)`。

- `s`：**カードの配置**。各スロットのスタック（下から上への色列）を 5 スロット分並べたもの。
  発火後の連鎖では下層の色が露出して効くため、最上段だけでなくスタックを保持する。
  ただし **1 ターンの勝敗に寄与するのは各スロットの上から数枚だけ**（そのターンの連鎖で露出しうる範囲）なので、実用上は各スロットを **上から `K` 枚（初期 `K = 7`）で切り詰めて** 状態表現とし、それより下層は捨象する。`K` は完成後に感度分析する（§7・§8）。
- `t`：**ターン位相**。直前の配置がどのコンテキストで行われたかを表す最小限の情報。
  - `t = own`：自分の手番での配置（最初の 2 枚の配置、および連鎖中の追加ドロー配置）。**発火判定が走る**。
  - `t = gift`：他者から配布されたカードの配置（`PLACE_GIFT`）。**発火判定が走らない**。

### 2.2 発火関数 fire(S)

```
fire(S) = ( s の最上段に同色 3 枚以上の組が存在する ) ∧ ( t = own )
```

`t` を状態に含める理由（ユーザー指摘の核心）：
同じ配置 `s` でも、

- 自手番の配置直後（`t = own`）なら → **即発火**してカードが除去され得点になる。
- プレゼント配置直後（`t = gift`）なら → **発火せず盤面に残る**。これは「次に自分が何か配置して解決フェーズに入った瞬間に発火する **遅延した仕込み**」になる。

この差は実ルール（`reducer.ts`）に由来する：`PLACE_DRAWN` / `PLACE_ADDITIONAL_DRAW` は配置完了後に `resolvingCombos` へ遷移するが、`PLACE_GIFT` は遷移しない。

### 2.3 状態空間の二分

- **発火状態**：`fire(S) = true` の状態。
- **非発火状態の集合 N**：`N = { S : fire(S) = false }`。

> **重要な力学**：自分の手番で配置して最上段に同色 3 枚以上ができたら、発火は **強制**（解決は自動ループ）。回避できない。
> よって「小さな発火（size3 = 1 点）を不用意に作る」と、大物を作るためのカードを消費してしまう。
> これは既知の AI の弱点「小コンボの即時回収」（`ai/CHANGELOG` / メモリ参照）と同じ穴であり、GRM はこれを **「G に入るまで N の中で積み増し、G で一気に発火させる」** という構造で原理的に回避することを狙う。

### 2.4 状態 S と観測コンテキスト C の分離

`S = (s, t)` は **アルゴリズムが最適化する対象（自分の盤面の積み方）の核** であり、`fire(S)` はこの `(s, t)` だけで決まる。
一方、`f` や `U` の **計算** には `(s, t)` 以外の観測情報が要る。これらを **観測コンテキスト `C`** としてまとめ、`f(S, V; C)`・`U(S; C)` のように `C` を引数に取ると整理できる（記述上は簡潔さのため `C` を省略する）。`C` に含めるもの：

| 情報 | 用途 |
|---|---|
| 自分の盤面（`s` 自身） | `fire`・`f`・`U` の中核 |
| 保留カード（`pendingDraw` 等） | 配置途中の状態の表現 |
| 場の 2 ペア | 今ターンの取得チャネル選択（§6.2） |
| 山札の枚数・捨札の色別枚数 | `deckCount(·)` の逆算＝ドロー確率（§1.3） |
| 全プレイヤーのスコア | 終盤の必要得点の算出（§6.6） |
| 手番順（`startPlayerIndex` からの距離） | 同点タイブレークの判定（§6.6） |
| 最終ラウンド情報（`endTriggered` 等） | 終盤モードの発動判定（§6.6） |

`f` は主に `C` 中の **山札の色分布** を、終盤の `U`／§6.6 は主に **スコア・手番順・最終ラウンド情報** を使う。

## 3. 二値の閾値 V, P

- `V`：**目標点数**＝「1 ターンの連鎖で取りに行く点数」（累計スコアではなく、その 1 ターンの瞬間火力）。基本値 20。
  - 1 コンボの最大サイズは 5（＝スロット数）で size5 = 10 点。よって `V = 20` は単発では不可能で、**連鎖の継続と本数ボーナスを前提とした「大連鎖狙い」** を意味する。
  - **基本戦略**：小刻みに得点を貯めず、`V = 20` 点ぶんの大連鎖を仕込んでから **一撃で 20 点以上を取り、その場で勝負を決める（しとめる）**。自分が小さく早く 20 点へ到達して最終ラウンドを誘発し、後続プレイヤーに最後の一撃の機会を与えてしまうのを避ける狙い。
  - 終盤（最終ラウンド）の `V` 動的更新と `P` 無効化は §6.6。
- `P`：**目標確率**。集合 `G` を切り出す確率閾値。シミュレーションで決定（初期値 80% 程度）。

得点の定義（`scoring.ts`）：

```
ターン得点 = Σ basePointsForSize(各コンボのサイズ) + comboCountBonus(コンボ本数 n)
basePointsForSize: 3→1, 4→3, 5→10, k(≥6)→10+(k−5)·5
comboCountBonus(n) = n(n−1)/2        （n=2:1, 3:3, 4:6, 5:10, …）
```

## 4. 発火後サブゲームと f(S,V)

### 4.1 サブゲームの力学

発火状態 `S` を起点に、ルールに従って連鎖を解決していく。1 ステップは次の通り（`reducer.ts: resolveChainStep`）：

1. **解決**：最上段に同色 3 枚以上の色を **すべて同時に** 検出・除去し、得点とコンボ本数に加算（複数色が同時に揃えば 1 ステップで複数本）。
2. **追加アクションの選択**（プレイヤーの制御点）。次のいずれか一方：
   - **削除**：いずれかのスロットの最上段 1 枚を取り除く（下層の色が露出 → 新たな 3 枚を作れることがある）。
   - **ドロー & 配置**：山札から 1 枚引き（色はランダム）、いずれかのスロットに積む。山札が空なら捨札をリシャッフル（§1.3）。
3. 配置／削除後、再び 1. へ。新たな発火が無くなったらサブゲーム終了 → ターン得点が確定。

**終端条件**：(i) 新たな発火が無くなったとき。(ii) 追加アクションが **どちらも不能** のとき — すなわち山札・捨札がともに空で「ドロー」できず、かつ自分のボードが空で「削除」もできない場合は、選択肢が無いので **そのステップで強制的に得点確定へ進む**（`reducer.ts: resolveChainStep` の自動スキップ）。`f` の後退帰納でもこの 2 つを終端とする。

### 4.2 f(S,V) の定義

追加アクションの選び方を方策 `π`（各ステップで「削除か／ドローしてどこへ置くか」を決める）とすると、

```
f(S, V) = max_π  P_π( ターン得点 ≥ V  |  発火状態 S から連鎖開始 )
```

- ランダム性はドローの色のみ（山札の色分布、§1.3 の場合分けに従う）。削除・配置先・どちらを選ぶかは制御変数。
- 連鎖はカードが減るため有限ステップで必ず終わる → サブゲームは有限（§4.1 の 2 終端条件で必ず停止）。
- したがって `f(S,V)` は **確率付き後退帰納（または期待値 DP）で厳密に解ける**（外側 `U` の `R(C)` 期待評価とは性格が異なる — §6・§7）。DP 状態は (盤面, これまでのコンボ本数・各サイズ, **山札の色分布, 捨札の色分布**)、終端報酬は「得点 ≥ V」の指示関数。捨札の色分布も持つのは、連鎖中の追加ドローで山札が尽きると捨札がリシャッフルされて山札になる（§1.3）ため — これを追わないとリシャッフル後のドロー確率が計算できない。

`f` は「発火状態 `S` と目標点 `V` を与えると確率 `p` が定まる」関数であり、ユーザー定義の `f(S,V) = p` に一致する。

## 5. 目標発火状態集合 G と非発火集合 N

```
G(V, P) = { S : fire(S) = true  ∧  f(S, V) ≥ P }
N       = { S : fire(S) = false }
```

- `G(V,P)`：**発火させれば V 点以上を確率 P 以上で取れる発火状態**の集合。「ここまで持って行けば勝負手になる」到達目標。
- `N`：非発火状態。AI が普段滞在し、遷移していく空間。

---

## 6. 主方策：N から G への最大到達確率計画

AI は非発火状態 `N` の中を遷移し、`G(V,P)` の元へ到達することを目指す。到達したターンで発火させ、確率 `f(S,V) ≥ P` で `V` 点を取る。

**設計方針：相手の戦略・手選択は読まない。** `U`・`f` は自分のボードと観測可能情報（場・山札の色分布）だけで計算する。相手手番をまたぐ未来のコンテキスト（場の補充・山札消費など）は、相手の意思決定を仮定せず **ランダム外生モデル `R` で期待評価**（§6.2 の `U_random`）し、実際に次の自手番が来たら **観測済みの実状態で再計算** する（§6.2・§7）。相手への関与は次の 2 点に限る — (1) 終盤の `V` 更新で相手の **スコア（観測事実）** を参照する（§6.6。手を読むのではない）、(2) 配り手で相手の **現盤面** への害を最小化する（§6.5）。自分が `V` 点取った後に後続プレイヤーが上回るリスクも読まず、「できるだけ大きく取る」ことで間接的に抑える。

### 6.1 状態価値 U(S)

非発火状態 `S ∈ N` に対し、

```
U(S) = 最適に行動したとき、いずれ 目標集合 G(V,P) に到達できる確率
```

`G` は「発火させれば V 点以上を確率 P 以上で取れる状態」（§5）なので、`G` への到達をそのまま「成功」とみなす。`G` 未満の発火（`fire` だが `f < P`）に落ちるのは「成功確率の低い小〜中発火でターンを消費した」＝ **失敗** として扱う（§6.2 の `g`）。

> **理想形と実装形**（§6・§7 で区別）：理想形の `U` は多ターンにわたる最大到達確率。ただし本設計では **相手の戦略・手選択は読まず**、未来コンテキストをランダム外生モデル `R` で期待評価する（§6.2 の `U_random`）。実装形は「各自手番で、その時点の観測コンテキスト `C` から `G` 到達を計算し、`H` 手番で再帰を打ち切る。実際の次手番では観測済みの実 `C` で計算し直す」運用とする。内側 `f` の「厳密に解ける」（§4）とは性格が異なる。

### 6.2 自分の手番 1 回のダイナミクス

非発火状態 `S` で自手番が来たとき、決める変数は 2 段：

- **取得チャネル `a`**：
  - 場のペア 0 を取る／場のペア 1 を取る → 得る 2 枚の色は **確定**。
  - 山札から引く（通常 2 枚、残り 1 枚なら 1 枚に縮退）→ 得る色は **超幾何分布**（2 枚なら 15 通りの色組、§1.3）。
- **積み方 `d`**：得たカード列（通常 2 枚、残り 1 枚なら 1 枚）を 5 スロットへどう積むか（各カードのスロット選択。同一スロットに重ねることも可）。
  発火判定は **手に入れた分をすべて置き終えてから** 走る（`reducer.ts`：保留カードが残る間は解決に進まない）。

ドロー結果を `ω`（**今ターンに引く分のみ**。未来の場ペアは含めない）、配置後の状態を `S'(a, d, ω)` とすると、

```
U(S) = max_a  E_ω[ max_d  g( S'(a, d, ω) ) ]

          ┌ 1              … S' ∈ G(V,P)            （勝負手に到達＝成功）
g(S') =  ┤ 0              … fire(S') ∧ S' ∉ G(V,P) （G 未満の小〜中発火＝失敗）
          └ U_random(S')   … fire(S') = false        （非発火＝次の自手番へ）
```

- `max_a`：取得チャネルの選択（＝ユーザー構想の「最良の得方：セットを得るか山札からか」）。
- `E_ω`：山札ドローなら **今ターンに引く分**（通常 2 枚、残り 1 枚なら 1 枚に縮退）の色組の超幾何期待値、場のペアなら確定（縮退）。
- `max_d`：手に入ったカード列に対する最良の積み方（＝「最良の積み方」）。
- **同率タイブレーク**：複数の `(a, d)` が同じ値を与えるとき（特に複数手が `G` に到達して `g = 1` で並ぶとき）は、`f(S', V)` の大きい方＝より確実に・大きく取れる発火状態を選ぶ。
- **非発火枝 `U_random(S')`**：`fire(S') = false` ならそのターンは終了。次に自分の手番が来た時点の状態を評価するが、**相手の戦略・手選択は読まない**。そこで次自手番の観測コンテキスト `C_next`（場ペア・山札枚数・捨札色数など）を、相手の意思決定を読まない **ランダム外生モデル `R(C)`** で生成し、その期待をとる：

  ```
  U_random(S') = E_{C_next ~ R(C)} [ U(S' ; C_next) ]
  ```

  これは「相手の戦略は読まないが、非発火の積み方同士を比較するために、未来コンテキストをランダム外生変数として期待評価する」という意味。実際に次の自手番が来たら、`R` の期待ではなく **観測済みの実状態** で `U` を計算し直す。実装上は `H` 手番で再帰を打ち切る（§7）。`R(C)` の具体は §8。

この式が、ユーザーの「全ての得方（取得カード列 1〜2 枚）について、G に到達するにはどう積むか考え、最良の得方と最良の積み方を選ぶ」を厳密化したもの。

### 6.3 小発火を避ける仕組み

これは副作用的な創発ではなく、目的（`G` 到達）の定義そのものから来る **能動的な排除** である。

小発火（例：size3 = 1 点）は (1) カードを消費し、(2) そのターンの得点を小さく確定させるため、`V` が高いほど **そのターンに V 点へ届く道をほぼ断つ** → `f(小発火状態, V) ≈ 0 < P`。つまり小発火は定義上 `G(V,P)` に入らない。
ゆえに §6.2 の `g` では小発火は `g = 0`（失敗）と評価され、将来性が残る積み増し（`U(S') > 0`）に劣る。`max_d` はこれを **積極的に避ける**。§2.3 の弱点（小コンボの即時回収）は、専用のペナルティを足さずとも、`G` を高い `V` で定義することだけで断たれる。

### 6.4 プレゼント受領時の配置

他者からカードを配られたとき（`PLACE_GIFT`、色は既知・確定）：

- このフェーズでは発火しない（`t = gift`）。配置で最上段 3 枚以上を作っても **残るだけ**＝次の自手番の解決で発火する仕込みになる。
- 配置先 `d` は、配置後状態の `U(S')` を最大化するよう選ぶ（複数枚なら逐次）。
  - 自分に有利なら：次ターンで `G` に直結する仕込みを作る。
  - 不利な色なら：将来の連鎖を壊さないスロット（捨て筋のスロット等）へ逃がす。
- §6.2 と同じ「`U` 最大化」の枠組みで統一的に扱える。

### 6.5 配り手（CONFIRM_GIFTS）

各コンボから 1 枚を選んで他者へ配り、残りは捨札にする（`reducer.ts: handleConfirmGifts`）。
方針：**相手の盤面評価が極力上がらない配り方を選ぶ**。相手の手は読まないが、配るカードが相手の連鎖を助けない最小限の配慮はする（＝塩を送らない）。
配るカードの色と配り先の組について、相手の現盤面にそのカードを加えたときの **連鎖準備度の上昇が最も小さい**（理想的には上がらない）組を選ぶ。相手評価は相手盤面の簡易指標（最上段同色のリーチ進行など）で測り、相手の将来手は読まない。能動的妨害（相手評価を最大限 **下げる** 最適化）まではしない。

### 6.6 終盤の目標切り替え（しとめ／追い込みモード）

**発動条件**：自分の手番開始時に、すでに **他プレイヤーが 20 点以上に到達している**（＝同ラウンド内で自分以外の誰かが終了条件を満たし、最終ラウンドに突入済み＝`engine.ts` の `endTriggered` が他者を引き金に立っている）場合。これに当てはまらない通常時は §6.1–6.5（`V = 20`、`G(V,P)` まで温存）のまま。発動時は次の 2 点を切り替える。

**(a) 勝利に必要な「追加得点」への `V` の更新**：通常の `V` は「このターンの得点」なので、相手の **累計** スコアをそのまま `V` に入れてはならない。自分の現在累計を `s_me`、勝つために超えるべき相手の累計を `s_win` とすると、

```
V(終盤) = max( 0,  s_win − s_me + 1 )      // このターンに必要な追加得点
```

`s_win` の決め方（`engine.ts: computeWinner` に従う。同点は `startPlayerIndex` に近い＝手番が先の側が勝ち）：

- 超えるべき相手＝ **自分より手番が先で、同点では自分が負ける** プレイヤー。その中の最高累計が `s_win`（相手が 21 点なら `V = 22 − s_me`）。複数が 20 点以上でも、この最高累計の 1 人を見れば足りる。
- 自分より **手番が後** のプレイヤーには同点でも自分が勝つので `s_win` の対象にしない（彼らの逆転は §6 冒頭の方針どおり読まない）。
- 自分が **すでに暫定勝者**（`s_win − s_me + 1 ≤ 0`）なら **終盤モード自体を解除** し、通常運用（§6.1–6.5、`V = 20`・`P` 使用）に戻る。追い込み（下記 (b) の `P` 無効化）は行わず、無理な大連鎖を狙わずに §6.5 の「塩を送らない」を優先する。

**(b) `P` 閾値の無効化（argmax f）**（追い込みが必要な＝上記 `V(終盤) > 0` の場合）：このとき自分の残り手番は尽きる（多くは今ターンが最後）。`U` の多ターン再帰の前提が崩れるため、「`P` に満たなければ温存して見送る」は成立しない（見送り＝負け確定）。よってこのモードでは `P` を捨て、**とにかく今ターンで発火させ、`V` 以上を取れる確率 `f` が最大の手を選ぶ**：

```
最良手 = argmax_{取得チャネル a, 積み方 d}  E_ω[ fire(S') ? f(S', V) : 0 ]
         ただし S' = S'(a, d, ω)。次の自手番が無いので、6.2 の g の
         非発火枝 U(S') を 0 に潰した H=1 の特殊形。P フィルタはしない。
```

確率が低くても、それが唯一の勝ち筋である限り選ぶ。

## 7. 近似と実装上の選択肢

内側 `f` は連鎖サブゲームとして **厳密に解ける**（§4）。一方、外側 `U` は本設計では **相手戦略を読まず、未来コンテキストを `R(C)` で期待評価し、実際の次自手番では観測状態で再計算する運用**（§6.1・§6.2）なので、理想形（多ターン最大到達確率）と実装形を分けて扱う。実装では以下を選ぶ。

- **ホライズン `H`（時間方向）**：`U` の再帰を `H` 手番で打ち切る。末端で `G` 未到達なら 0、または `f` の最大見込みで近似。`H = 1`（今ターンで `G` に入れるかだけを見る貪欲）から検証し、必要なら増やす。
- **状態の深さ `K`（空間方向）**：各スロットを上から `K` 枚（初期 7）で切り詰めて状態表現とする（§2.1）。下層は勝敗に寄与しないとみなす。`H` とは独立な軸。
- **ドローの確率の扱い**：山札 2 枚なら 15 通りの色組を **超幾何で厳密**に重み付け（分岐は高々 15）、残り 1 枚なら 5 通りに縮退。連鎖中の単発ドローも同様（5 通り）。サンプリング近似は不要（厳密が現実的）。
- **`P` の決定**：自己対戦シミュレーションで、勝率が最大化される `P` を探索（初期値は §3）。
- **`V` の設定**：基本 20。終盤は §6.6 で動的更新。
- **相手モデル／未来：戦略は読まない・未来はランダム外生期待**（§6 冒頭の設計方針）。具体的には：
  - **今の自分のターンで取る場のペア** は確定情報として考慮する。
  - **次のターン以降のコンテキスト**（場ペア・山札枚数・捨札色数）は、相手の戦略・手選択を読まずに **ランダム外生モデル `R(C)` の期待値** として扱う（`U_random`、§6.2）。実際に次の自手番が来たら、観測済みの実状態で計算し直す。
  - **被プレゼント（自分が受け取る贈り物）は基本的に来ない** ものとして計算する（実際に届いたら §6.4 で配置を最適化）。

## 8. 未確定事項（後で詰める）

本書で論理補完した点、または完成後に感度分析する点。

1. **ホライズン `H`・深さ `K` の値**：`U` を何手番先まで再帰するか（`H`）、状態を各スロット上から何枚で切るか（`K`、初期 7）。いずれも完成後に変えて寄与を測る（§2.1・§7）。
2. **`U` の割引**：早く `G` に着く手をどう優先するか（手数ペナルティ／割引）。
3. **複数の発火経路**：`f` のサブゲームで「削除」と「ドロー配置」の分岐爆発をどこまで厳密に解くか（深さ上限／枝刈り）。
4. **`G` の事前計算可否**：`G` は陽に列挙せず、`U` 計算中に `f(S',V) ≥ P` を都度判定する遅延評価で十分か。
5. **配り手の評価指標（§6.5）**：相手盤面の「連鎖準備度の上昇」をどの式で測るか。
6. **外生モデル `R(C)` の具体（§6.2 の `U_random`）— この仕様で残る最後の大きな未定義点**：次自手番のコンテキスト（場ペア補充・山札消費・捨札変化）を、相手戦略を読まずにどう生成するか。最も単純には「場ペアは未観測プールからランダム補充・山札は一定枚数だけ減少・捨札は不変」など。これは `U` の再帰（`H ≥ 2`）で非発火手を評価するときにのみ必要なので、実装順序は「`f` → `U`(`H=1`、貪欲) → `R(C)` を定めて `U`(`H≥2`)」とでき、`R(C)` の確定は後段まで遅らせられる。
