# 目標到達確率最大化法（GRM: Goal-Reachability Maximization）

「星を放つ夜」CPU のための、**完全アルゴリズム的**な手番決定ロジックの仕様。

> 用語は tstar リポジトリの TSTAR.md を正とする（旧表記: f=q, U=T̂）。

## 0. 位置づけと命名

### 0.1 なぜ「AI」でなく「アルゴリズム」か

本手法は学習（NN・棋譜模倣）も、手書きヒューリスティック評価関数（テンポ評価のような近似スコア）も用いない。
代わりに、ゲームの確率構造を直接解いて **「狙うべき発火状態の集合」への到達確率を最大化する** 決定論的プランナーである。
出力は「ある仮定（観測情報＋確率モデル）の下での最適解」であり、推測やパラメータ職人芸を含まない。この意味で狭義の AI ではないため、本書では「法／プランナー」と呼ぶ。

### 0.2 既存路線との違い

- 探索 + 手書き評価関数の AI（Gen-15 までの現状最強 `tempoFastAI` 等）は、**葉（ターン終了局面）の良し悪しをヒューリスティックなスコアで近似**しており、そこが律速・天井とされてきた（`ai/README.md`）。〔Gen-15 で現状最強は目的志向ポリシー `tempoChainAI` に交代。本書 GRM は葉の価値を確率量に置換する**別アプローチ**として独立に有効〕
- GRM は、この「葉の価値」を **明示的な確率量** `q(S,V) = P(このターン V 点以上)` に置き換える。評価関数の重み調整ではなく、サブゲームを解いて確率を直接求める。

### 0.3 構造：入れ子の到達目標最適化

本手法は「ある目標集合への到達」を二段で入れ子にしたものである。

- **内側** `q(S,V)`：発火後の連鎖サブゲームで「得点 ≥ V」へ到達する確率の最大化。
- **外側** `T̂(S)`：非発火状態の列を遷移し、良い発火状態集合 `G` へ **最短（期待ターン数最小）で到達** する計画。
  〔当初は外側も到達確率の最大化として定式化していたが、確率は飽和して盤面間の差（勾配）が立たないため、**G 到達までの期待ターン数の最小化** に改めた（§6.1）。〕

内側 `q` は確率的システムにおける **maximal reachability probability**（目標集合への最大到達確率）であり、連鎖サブゲームとして後退帰納で **厳密に解ける**。外側 `T̂` は **確率的最短路（SSP）の最適期待到達ターン数 `T*`** を理想形とし、相手の戦略を読まず、山札ドローの確率モデルの下で **候補盤面ごとのヒューリスティックで近似** する（§6・§7）。

## 1. 前提：観測情報と確率モデル

実装・確率計算の土台。`src/ai/infoSet.ts` の観測情報集合に準拠する。

### 1.1 可視情報（手番プレイヤー視点）

- 全プレイヤーのボード（各スロットのスタックを、色も積み順も完全に）
- 場の 2 ペア（`field[0]`, `field[1]`、各 2 枚の色）
- 捨札の **色別枚数**
- 山札の **枚数**

### 1.2 不可視情報

- 山札の中身の **順序**（次に何色を引くか）のみ。

### 1.3 山札の色分布とドローのモデル化（確率の基礎）

各色は **24 枚固定**（5 色 × 24 = 120）。したがって任意時点で、色 `c` の **山札内** 枚数は

```
deckCount(c) = 24 − (全ボード上の c) − (場の c) − (捨札の c)
                  − (保留カードの c) − (連鎖中に除去済み・未処理の c)
```

で **完全に逆算できる**（捨札は別途、色別枚数が可視）。最後の項「連鎖中に除去済み・未処理」は、当ターンに発火して盤面から除かれたが、まだ捨札／プレゼントとして処理されていないカード（`combosThisTurn` / `giftQueue` 相当）を指す。`q` のサブゲーム計算中はこれらも山札に存在しないので、忘れず除外する。山札の順序のみ不可視なので、ドローは「山札の色内訳からの **非復元一様抽出（超幾何分布）**」としてモデル化する。

**実ルールに沿った場合分け**（`engine.ts: drawFromDeck` / `refillField`）：

- **山札が残っている間は山札からのみ引く**。捨札は混ざらない（＝「山札 ∪ 捨札」を一つのプールとして扱ってはならない）。確率は `deckCount(·)` の色内訳に対する超幾何。
- **山札が空になったときだけ** 捨札をリシャッフルして山札に戻す。以降のドローは、その（元・捨札の）色内訳に対する超幾何になる。1 ターンの連鎖で引く枚数は通常そこまで多くないが、境界をまたぐ場合はプールが切り替わる。
- **2 枚目が引けない場合は 1 枚ドローに縮退** する（`DRAW_FROM_DECK` で山札残り 1 枚など）。

> **帰結**：山札から 2 枚引いたときの色の組は 15 通り（5 色から重複ありで 2 枚）で、各確率は上記の超幾何から **厳密に** 定まる（ユーザー構想の「2 枚の得方は 15 通り・同様に確からしくない」の数学的実体）。場のペアを取る場合は色が確定（確率 1）。

## 2. 状態 S の定義

### 2.1 構成要素

状態 `S = (s, t)`。

- `s`：**カードの配置**。各スロットのスタック（下から上への色列）を 5 スロット分並べたもの。
  発火後の連鎖では下層の色が露出して効くため、最上段だけでなくスタックを保持する。
  ただし **1 ターンの勝敗に寄与するのは各スロットの上から数枚だけ**（そのターンの連鎖で露出しうる範囲）なので、実用上は各スロットを **上から `K` 枚で切り詰めて** 状態表現とし、それより下層は捨象する（初期 7 → 現行はプレイ実装 `grmAI` の既定 **6**。`q` 単体 `reachQ` の既定は 7 のまま）。`K` は完成後に感度分析する（§7・§8）。
- `t`：**ターン位相**。直前の配置がどのコンテキストで行われたかを表す最小限の情報。
  - `t = own`：自分の手番での配置（最初の 2 枚の配置、および連鎖中の追加ドロー配置）。**発火判定が走る**。
  - `t = gift`：他者から配布されたカードの配置（`PLACE_GIFT`）。**発火判定が走らない**。

### 2.2 発火関数 fire(S)

```
fire(S) = ( s の最上段に同色 3 枚以上の組が存在する ) ∧ ( t = own )
```

`t` を状態に含める理由（ユーザー指摘の核心）：
同じ配置 `s` でも、

- 自手番の配置直後（`t = own`）なら → **即発火**してカードが除去され得点になる。
- プレゼント配置直後（`t = gift`）なら → **発火せず盤面に残る**。これは「次に自分が何か配置して解決フェーズに入った瞬間に発火する **遅延した仕込み**」になる。

この差は実ルール（`reducer.ts`）に由来する：`PLACE_DRAWN` / `PLACE_ADDITIONAL_DRAW` は配置完了後に `resolvingCombos` へ遷移するが、`PLACE_GIFT` は遷移しない。

### 2.3 状態空間の二分

- **発火状態**：`fire(S) = true` の状態。
- **非発火状態の集合 N**：`N = { S : fire(S) = false }`。

> **重要な力学**：自分の手番で配置して最上段に同色 3 枚以上ができたら、発火は **強制**（解決は自動ループ）。回避できない。
> よって「小さな発火（size3 = 1 点）を不用意に作る」と、大物を作るためのカードを消費してしまう。
> これは既知の AI の弱点「小コンボの即時回収」（`ai/CHANGELOG` / メモリ参照）と同じ穴であり、GRM はこれを **「G に入るまで N の中で積み増し、G で一気に発火させる」** という構造で原理的に回避することを狙う。

### 2.4 状態 S と観測コンテキスト C の分離

`S = (s, t)` は **アルゴリズムが最適化する対象（自分の盤面の積み方）の核** であり、`fire(S)` はこの `(s, t)` だけで決まる。
一方、`q` や `T̂` の **計算** には `(s, t)` 以外の観測情報が要る。これらを **観測コンテキスト `C`** としてまとめ、`q(S, V; C)`・`T̂(S; C)` のように `C` を引数に取ると整理できる（記述上は簡潔さのため `C` を省略する）。`C` に含めるもの：

| 情報 | 用途 |
|---|---|
| 自分の盤面（`s` 自身） | `fire`・`q`・`T̂` の中核 |
| 保留カード（`pendingDraw` 等） | 配置途中の状態の表現 |
| 場の 2 ペア | 今ターンの取得チャネル選択（§6.2） |
| 山札の枚数・捨札の色別枚数 | `deckCount(·)` の逆算＝ドロー確率（§1.3） |
| 全プレイヤーのスコア | 終盤の必要得点の算出（§6.6） |
| 手番順（`startPlayerIndex` からの距離） | 同点タイブレークの判定（§6.6） |
| 最終ラウンド情報（`endTriggered` 等） | 終盤モードの発動判定（§6.6） |

`q` は主に `C` 中の **山札の色分布** を、終盤の `T̂`／§6.6 は主に **スコア・手番順・最終ラウンド情報** を使う。

## 3. 二値の閾値 V, P

- `V`：**目標点数**＝「1 ターンの連鎖で取りに行く点数」（累計スコアではなく、その 1 ターンの瞬間火力）。基本値 20。
  - 1 コンボの最大サイズは 5（＝スロット数）で size5 = 10 点。よって `V = 20` は単発では不可能で、**連鎖の継続と本数ボーナスを前提とした「大連鎖狙い」** を意味する。
  - **基本戦略**：小刻みに得点を貯めず、`V = 20` 点ぶんの大連鎖を仕込んでから **一撃で 20 点以上を取り、その場で勝負を決める（しとめる）**。自分が小さく早く 20 点へ到達して最終ラウンドを誘発し、後続プレイヤーに最後の一撃の機会を与えてしまうのを避ける狙い。
  - 終盤（最終ラウンド）の `V` 動的更新と `P` 無効化は §6.6。
- `P`：**目標確率**。集合 `G` を切り出す確率閾値。シミュレーションで決定（初期値 80% 程度）。

得点の定義（`scoring.ts`）：

```
ターン得点 = Σ basePointsForSize(各コンボのサイズ) + comboCountBonus(コンボ本数 n)
basePointsForSize: 3→1, 4→3, 5→10, k(≥6)→10+(k−5)·5
comboCountBonus(n) = n(n−1)/2        （n=2:1, 3:3, 4:6, 5:10, …）
```

## 4. 発火後サブゲームと q(S,V)

### 4.1 サブゲームの力学

発火状態 `S` を起点に、ルールに従って連鎖を解決していく。1 ステップは次の通り（`reducer.ts: resolveChainStep`）：

1. **解決**：最上段に同色 3 枚以上の色を **すべて同時に** 検出・除去し、得点とコンボ本数に加算（複数色が同時に揃えば 1 ステップで複数本）。
2. **追加アクションの選択**（プレイヤーの制御点）。次のいずれか一方：
   - **削除**：いずれかのスロットの最上段 1 枚を取り除く（下層の色が露出 → 新たな 3 枚を作れることがある）。
   - **ドロー & 配置**：山札から 1 枚引き（色はランダム）、いずれかのスロットに積む。山札が空なら捨札をリシャッフル（§1.3）。
3. 配置／削除後、再び 1. へ。新たな発火が無くなったらサブゲーム終了 → ターン得点が確定。

**終端条件**：(i) 新たな発火が無くなったとき。(ii) 追加アクションが **どちらも不能** のとき — すなわち山札・捨札がともに空で「ドロー」できず、かつ自分のボードが空で「削除」もできない場合は、選択肢が無いので **そのステップで強制的に得点確定へ進む**（`reducer.ts: resolveChainStep` の自動スキップ）。`q` の後退帰納でもこの 2 つを終端とする。

### 4.2 q(S,V) の定義

追加アクションの選び方を方策 `π`（各ステップで「削除か／ドローしてどこへ置くか」を決める）とすると、

```
q(S, V) = max_π  P_π( ターン得点 ≥ V  |  発火状態 S から連鎖開始 )
```

- ランダム性はドローの色のみ（山札の色分布、§1.3 の場合分けに従う）。削除・配置先・どちらを選ぶかは制御変数。
- 連鎖はカードが減るため有限ステップで必ず終わる → サブゲームは有限（§4.1 の 2 終端条件で必ず停止）。
- したがって `q(S,V)` は **確率付き後退帰納（または期待値 DP）で厳密に解ける**（外側 `T̂` の `R(C)` 期待評価とは性格が異なる — §6・§7）。DP 状態は (盤面, これまでのコンボ本数・各サイズ, **山札の色分布, 捨札の色分布**)、終端報酬は「得点 ≥ V」の指示関数。捨札の色分布も持つのは、連鎖中の追加ドローで山札が尽きると捨札がリシャッフルされて山札になる（§1.3）ため — これを追わないとリシャッフル後のドロー確率が計算できない。

`q` は「発火状態 `S` と目標点 `V` を与えると確率 `p` が定まる」関数であり、ユーザー定義の `q(S,V) = p` に一致する。

## 5. 目標発火状態集合 G と非発火集合 N

```
G(V, P) = { S : fire(S) = true  ∧  q(S, V) ≥ P }
N       = { S : fire(S) = false }
```

- `G(V,P)`：**発火させれば V 点以上を確率 P 以上で取れる発火状態**の集合。「ここまで持って行けば勝負手になる」到達目標。
- `N`：非発火状態。AI が普段滞在し、遷移していく空間。

---

## 6. 主方策：N から G への最大到達確率計画

AI は非発火状態 `N` の中を遷移し、`G(V,P)` の元へ到達することを目指す。到達したターンで発火させ、確率 `q(S,V) ≥ P` で `V` 点を取る。

**設計方針：相手の戦略・手選択は読まない。** `T̂`・`q` は自分のボードと観測可能情報（場・山札の色分布）だけで計算する。相手手番をまたぐ未来のコンテキスト（場の補充・山札消費など）は、相手の意思決定を仮定せず **ランダム外生モデル `R` で期待評価**（§6.2 の `T̂_random`）し、実際に次の自手番が来たら **観測済みの実状態で再計算** する（§6.2・§7）。相手への関与は次の 2 点に限る — (1) 終盤の `V` 更新で相手の **スコア（観測事実）** を参照する（§6.6。手を読むのではない）、(2) 配り手で相手の **現盤面** への害を最小化する（§6.5）。自分が `V` 点取った後に後続プレイヤーが上回るリスクも読まず、「できるだけ大きく取る」ことで間接的に抑える。

### 6.1 状態価値 T̂(S)

非発火状態 `S ∈ N` に対し、

```
T̂(S) = 最適に積み増したとき、目標集合 G(V,P) に到達するまでの 期待自手番数（少ないほど良い）
```

当初は「いずれ G に到達できる確率」で定義していたが、到達確率は飽和して（近い盤面も遠い盤面も ~1 や ~0 になり）盤面間の差＝勾配が立たないため、**G 到達までの期待ターン数**に置き換えた。少ないほど G に近く、あらゆる局面で連続な勾配が得られる。戦略的にも「相手が 20 点に達する前に、自分が最短で勝負手 G に到達する」テンポ戦に一致する。

`G` は「発火させれば V 点以上を確率 P 以上で取れる状態」（§5）。`G` 未満の発火（`fire` だが `q < P`）に落ちるのは「成功確率の低い小〜中発火で setup を潰した」＝ **失敗（最悪）** として扱う（§6.2 の `g`）。

#### 6.1.1 厳密な真値 T*（理想形・近似のベンチマーク）

`T̂(S)` の理想形は、次の単純化モデルの下での **最適期待到達ターン数 `T*(S)`** として厳密に定義できる。

- **モデル**：次ターン以降は毎ターン、固定の色分布（山札の色割合）から **2 枚が i.i.d. ランダムに与えられ**、それを 5 スロットへ **最適に配置** する。山札の消費・リシャッフルは定常とみなし状態に含めない。状態は自分の盤面（順序込み・各スロット上から `K` 枚で切り詰め）のみ。
- **ベルマン方程式**（有限状態の確率的最短路 SSP）：
  ```
  T*(s) = 0                                        （s ∈ G）
  T*(s) = 1 + Σ_ω P(ω) · min_d  T*( s'(s, d, ω) )   （それ以外）
  ```
  `ω` は与えられる 2 枚の色組（確率付き）、`d` は配置（こちらが最小化）。`s'(s,d,ω) ∈ G` ならその枝は 0（そのターンで到達）。
- **V=20 では `T*` は常に有限**：V=20 では適切に積めば `q = 1` の G（発火すれば確定で 20 点以上。主に削除による決定的連鎖）が **多数存在** する。i.i.d. ランダムドローは `d_c > 0` の色を無限回もたらすので、最適配置で **どの状態からも確率 1 で G を組み上げられる**。色分布の偏りは到達**ターン数を増やすだけ** で到達可能性は損なわない（極端な分布でも `T* = ∞` にはならない）。よって `T*(S)` は **全状態で有限**、SSP の一意解として厳密に定まる。
- **自己完結の数学的仕様**：`T*` の厳密定義（状態空間・q・ベルマン方程式・近似関数の契約）はゲーム実装に依存しない形で `ai/TSTAR.md` に切り出してある。近似手法の研究はそちらを正とする。

#### 6.1.2 近似でしか解けない

`T*` を全状態で厳密に解くのは状態数から **計算不能**：盤面を各スロット上から `K=6` 枚で切り詰め、色 5!・スロット 5! の対称性で割っても **約 10^17 状態**（実測でも到達閉包が発散）。さらに順番を捨てる抽象化は連鎖の順序依存（最上段を除くと下層が露出）上 **無意味** で使えない。そこで実装の `T̂` は、**候補盤面ごとに `T*` を軽量ヒューリスティックで近似** する（§6.2）。改良の目標は「`T̂` を真値 `T*` にどれだけ近づけるか」で、**小盤面（少色・浅 `K`・小 `V`）では `T*` を値反復で厳密に解けるので、近似誤差を測りながら改良できる**。内側 `q` の「厳密に解ける」（§4）とは性格が異なる。

### 6.2 自分の手番 1 回のダイナミクス

非発火状態 `S` で自手番が来たとき、決める変数は 2 段：

- **取得チャネル `a`**：
  - 場のペア 0 を取る／場のペア 1 を取る → 得る 2 枚の色は **確定**。
  - 山札から引く（通常 2 枚、残り 1 枚なら 1 枚に縮退）→ 得る色は **超幾何分布**（2 枚なら 15 通りの色組、§1.3）。
- **積み方 `d`**：得たカード列（通常 2 枚、残り 1 枚なら 1 枚）を 5 スロットへどう積むか（各カードのスロット選択。同一スロットに重ねることも可）。
  発火判定は **手に入れた分をすべて置き終えてから** 走る（`reducer.ts`：保留カードが残る間は解決に進まない）。
  **置く順序も選択変数**：同一スロットに 2 枚重ねる場合は上下順（先に置いた方が下）で別盤面になるため、実装は「先に置くカード × スロット」を全列挙して **順序込みで** 最適化する（`bestDrawnPlacement`。実配置・プレゼント受領配置も同じ順序完全探索）。

ドロー結果を `ω`（**今ターンに引く分のみ**。未来の場ペアは含めない）、配置後の状態を `S'(a, d, ω)` とすると、

```
T̂(S) = min_a  E_ω[ min_d  g( S'(a, d, ω) ) ]      ← 期待ターン数なので最小化（少ないほど良い）

          ┌ 0          … S' ∈ G(V,P)            （勝負手に到達＝このターンで成功）
g(S') =  ┤ 大ペナルティ … fire(S') ∧ S' ∉ G(V,P) （G 未満の小〜中発火＝setup を潰す＝失敗）
          └ T̂(S')      … fire(S') = false        （非発火＝積み増し継続。下の期待ターン見積り）
```

（実装では「大きいほど良い」`gValue = −期待ターン数` に符号反転して `max` を取る。G 到達 ≈ 0 で最良、小発火は大きな負、非発火は `−T̂`。）

- `min_a`：取得チャネルの選択（最良の得方：場ペア 0／場ペア 1／山札）。
- `E_ω`：山札ドローなら今ターンに引く分の色組の超幾何期待値、場のペアなら確定。
- `min_d`：手に入ったカード列に対する最良の積み方。
- **実装のチャネル評価**：場ペアは実カード 2 枚を順序込みで厳密に最適配置した値。山札は色組を列挙（やサンプリング）せず、**恒等式 `E_ω[ min_d cost ] = T(S) − 1`**（gValue 表現では `1 − T(S)`）で現盤面の期待ターン数 `T(S)`＝下記 `T̂` から直接導く——「山札の色分布から i.i.d. に 2 枚引いて最適配置する」は `T̂` が前提とするモデルそのものなので、別計算は不要で積み増し評価と完全に整合し、高速でもある。
- **同率タイブレーク**：同値の `(a, d)` は `q(S', V)` の大きい方を選ぶ。
- **非発火枝 `T̂(S')`（期待ターン数の見積り）**：到達確率は飽和して勾配が立たないので **G 到達までの期待ターン数** で評価する（§6.1）。全状態の値反復は状態数（~10^17）から不能なので、相手も未来も読まず、候補盤面ごとに **二段構え** で近似する：
  - **一段目（解析推定・全域）**：各色 `c` について、**実盤面に `c` を貪欲に積み、厳密 `q(盤面, V) ≥ P` になった最小枚数 `needed_c`** を求める（1 枚積むごとに `q` を判定し、G になった瞬間に止める＝改良C「過剰構築の抑制」）。**実スタックと厳密 `q` を使うので連鎖の順序依存を保つ**（順番を捨てる抽象化はしない）。`d_c` = 山札+捨札に占める `c` の割合（1 枚引いてその色である確率）。
  - `T̂`（解析推定）＝ **「どれか早い色で G に到達」する期待ターン数 `E[ min_c τ_c ]`**（改良A）。毎ターン 2 枚を i.i.d. に引き（色 c は確率 `d_c`、候補外は `q=1−Σd_c`）、色 c を `needed_c` 枚集めたらその色で G に届くとみなす。`E[τ] = Σ_t P(まだどの候補色も未達)`（多項分布の裾で厳密計算）。色は draw を共有して負相関なので、**単色 `min_c(needed_c/2d_c)`（min-of-means）より小さく（mean-of-min）、これが過大評価の主因を解消**する。候補は高々 2 色。どの色も上限内で G に届かなければ大ペナルティ。
  - **二段目（後退帰納・近距離のみ）**：解析推定が `GRM_REFINE_GATE`（3 ターン）以下の近距離盤面だけ、**深さ 1 の後退帰納** `T(S) = 1 + E_{2枚}[ min_配置 cost(S') ]` を実盤面・厳密 `q` の上で回す（厳密 `T*` のベルマン方程式 §6.1.1 と同じ漸化式）。配置を色で縛らず両積み順まで最適化するので、一段目の単色貪欲が見落とす **混在色の決定的連鎖** を厳密に拾う。小発火は不採用、深さ上限から先は一段目で埋める。後退帰納は値を下げる方向にしか効かないので、一段目を上界として min を取る。
  - これは外生モデル `R(C)`（§6 冒頭・§8）を「山札の色分布からのドロー」に単純化したものに相当する。相手の手・未来の場ペアは読まない。実際に次の自手番が来たら観測済みの実状態で再計算する。
  - **近似精度（実測）**：小盤面（2色・K=2・V=3）で厳密 `T*` と比較し、**平均絶対誤差 0.012 ターン・相関 0.99**（旧 `min/2d_c` 式 1.84／相関 0.66 → 改良A+C 0.15／0.85 → 二段構え 0.012／0.99）。ベンチは `ai/scripts/_tstar-bench.ts`。

この式が、ユーザーの「全ての得方について、G に到達するにはどう積むか考え、最良の得方と最良の積み方を選ぶ」を、**期待ターン数の最小化**として具体化したもの。

### 6.3 小発火を避ける仕組み

これは副作用的な創発ではなく、目的（`G` 到達）の定義そのものから来る **能動的な排除** である。

小発火（例：size3 = 1 点）は (1) カードを消費し、(2) そのターンの得点を小さく確定させるため、`V` が高いほど **そのターンに V 点へ届く道をほぼ断つ** → `q(小発火状態, V) ≈ 0 < P`。つまり小発火は定義上 `G(V,P)` に入らない。
ゆえに §6.2 の `g` では小発火は `g = 0`（失敗）と評価され、将来性が残る積み増し（`T̂(S') > 0`）に劣る。`max_d` はこれを **積極的に避ける**。§2.3 の弱点（小コンボの即時回収）は、専用のペナルティを足さずとも、`G` を高い `V` で定義することだけで断たれる。

### 6.4 プレゼント受領時の配置

他者からカードを配られたとき（`PLACE_GIFT`、色は既知・確定）：

- このフェーズでは発火しない（`t = gift`）。配置で最上段 3 枚以上を作っても **残るだけ**＝次の自手番の解決で発火する仕込みになる。
- 配置先 `d` は、配置後状態の `T̂(S')` を最大化するよう選ぶ（複数枚なら逐次）。
  - 自分に有利なら：次ターンで `G` に直結する仕込みを作る。
  - 不利な色なら：将来の連鎖を壊さないスロット（捨て筋のスロット等）へ逃がす。
- §6.2 と同じ「`T̂` 最大化」の枠組みで統一的に扱える。

### 6.5 配り手（CONFIRM_GIFTS）

各コンボから 1 枚を選んで他者へ配り、残りは捨札にする（`reducer.ts: handleConfirmGifts`）。
方針：**相手の盤面評価が極力上がらない配り方を選ぶ**。相手の手は読まないが、配るカードが相手の連鎖を助けない最小限の配慮はする（＝塩を送らない）。
配るカードの色と配り先の組について、相手の現盤面にそのカードを加えたときの **連鎖準備度の上昇が最も小さい**（理想的には上がらない）組を選ぶ。相手評価は相手盤面の簡易指標（最上段同色のリーチ進行など）で測り、相手の将来手は読まない。能動的妨害（相手評価を最大限 **下げる** 最適化）まではしない。

### 6.6 終盤の目標切り替え（しとめ／追い込みモード）

**発動条件**：自分の手番開始時に、すでに **他プレイヤーが 20 点以上に到達している**（＝同ラウンド内で自分以外の誰かが終了条件を満たし、最終ラウンドに突入済み＝`engine.ts` の `endTriggered` が他者を引き金に立っている）場合。これに当てはまらない通常時は §6.1–6.5（`V = 20`、`G(V,P)` まで温存）のまま。発動時は次の 2 点を切り替える。

**(a) 勝利に必要な「追加得点」への `V` の更新**：通常の `V` は「このターンの得点」なので、相手の **累計** スコアをそのまま `V` に入れてはならない。自分の現在累計を `s_me`、勝つために超えるべき相手の累計を `s_win` とすると、

```
V(終盤) = max( 0,  s_win − s_me + 1 )      // このターンに必要な追加得点
```

`s_win` の決め方（`engine.ts: computeWinner` に従う。同点は `startPlayerIndex` に近い＝手番が先の側が勝ち）：

- 超えるべき相手＝ **自分より手番が先で、同点では自分が負ける** プレイヤー。その中の最高累計が `s_win`（相手が 21 点なら `V = 22 − s_me`）。複数が 20 点以上でも、この最高累計の 1 人を見れば足りる。
- 自分より **手番が後** のプレイヤーには同点でも自分が勝つので `s_win` の対象にしない（彼らの逆転は §6 冒頭の方針どおり読まない）。
- 自分が **すでに暫定勝者**（`s_win − s_me + 1 ≤ 0`）なら **終盤モード自体を解除** し、通常運用（§6.1–6.5、`V = 20`・`P` 使用）に戻る。追い込み（下記 (b) の `P` 無効化）は行わず、無理な大連鎖を狙わずに §6.5 の「塩を送らない」を優先する。

**(b) `P` 閾値の無効化（argmax q）**（追い込みが必要な＝上記 `V(終盤) > 0` の場合）：このとき自分の残り手番は尽きる（多くは今ターンが最後）。`T̂` の多ターン再帰の前提が崩れるため、「`P` に満たなければ温存して見送る」は成立しない（見送り＝負け確定）。よってこのモードでは `P` を捨て、**とにかく今ターンで発火させ、`V` 以上を取れる確率 `q` が最大の手を選ぶ**：

```
最良手 = argmax_{取得チャネル a, 積み方 d}  E_ω[ fire(S') ? q(S', V) : 0 ]
         ただし S' = S'(a, d, ω)。次の自手番が無いので、6.2 の g の
         非発火枝 T̂(S') を 0 に潰した H=1 の特殊形。P フィルタはしない。
```

確率が低くても、それが唯一の勝ち筋である限り選ぶ。

## 7. 近似と実装上の選択肢

内側 `q` は連鎖サブゲームとして **厳密に解ける**（§4）。外側 `T̂`（積み増しの価値）は、全状態の値反復が
状態数（`K=6`・色/スロット対称性込みでも ~10^17。実測でも到達閉包が発散）から不能なので、
**候補盤面ごとの期待ターン数ヒューリスティック**で近似する（§6.1・§6.2）。実装では以下を選ぶ。

- **`T̂` の評価（時間方向）**：固定ホライズン `H` は **使わない**。二段構え（§6.2）＝一段目は単色貪欲の解析推定
  （`needed_c` と `E[min_c τ_c]`）、二段目は近距離（解析推定 ≤ `GRM_REFINE_GATE`=3）のみ深さ 1 の後退帰納で
  混在色・両積み順を厳密展開し、一段目を上界に min を取る。単色構築探索は枚数上限 `BUILD_CAP`（実装 14 枚 ≈
  2〜3 層）で打ち切る。実スタックと厳密 `q` を使うので順序依存を保つ。
- **取得チャネルの評価**：場ペアは実カード 2 枚の厳密最適配置（順序込み）。山札は恒等式 `1 − T(S)` で `T̂` の
  期待ターン数から直接導く（§6.2。色組の列挙・サンプリング不要）。
- **状態の深さ `K`（空間方向）**：各スロットを上から `K` 枚（プレイ実装 `grmAI` の既定 **6**。`q` 単体
  `reachQ` の既定は 7）で切り詰める（§2.1）。`q` の連鎖計算と `T̂` の構築探索の両方に効く。
- **ドローの確率の扱い**：`q`（連鎖中の単発ドロー）と取得チャネルの色は **超幾何で厳密**。`T̂` の積み増しは
  色ごとのドロー率 `2·d_c`（`d_c` = 山札+捨札の色割合）に単純化する（多ターンの構築コストの近似）。
- **`q` のノード予算**：`maxNodes` は **q 評価 1 回ごとにリセット** する（ソルバ生涯で累積させると、1 手に
  多数の q 評価を回した時点で上限超過の例外が誤発火し、実際に全手フォールバック退化バグの原因になった —
  `ai/CHANGELOG.md`）。上限超過は黙って打ち切らず例外で通知する（§8-3）。
- **`P` の決定**：自己対戦シミュレーションで勝率が最大化される `P` を探索（初期値は §3）。**`V` は固定 20 のまま
  動かさない**（下げると小コンボの即時回収に退化するため）。終盤のみ §6.6 で必要追加得点へ動的更新。調整ノブは実質 `P`（と `K`）。
- **相手モデル／未来：戦略は読まない**（§6 冒頭）。今ターンの場ペアは確定考慮、次ターン以降は読まず、被プレゼントは来ない前提。

## 8. 未確定事項（後で詰める）

本書で論理補完した点、または完成後に感度分析する点（コードからは項番で `§8-N` と参照する）。

1. **深さ `K`・構築上限 `BUILD_CAP`**：状態をスロット上から何枚で切るか（`K=6`）、`T̂` の単色構築探索を何枚で打ち切るか（`BUILD_CAP=14`）。完成後に変えて寄与を測る（§2.1・§7）。**固定ホライズン `H` は廃止**（期待ターン数ヒューリスティックへ移行したため不要）。
2. **`T̂` の指標**：到達「確率」は飽和して勾配が立たないため、**G 到達までの期待ターン数**（少ないほど良い）に置き換え済み（§6.1）。早着優先はこの指標自体が表現する。
3. **複数の発火経路**：`q` のサブゲームで「削除」と「ドロー配置」の分岐爆発をどこまで厳密に解くか（深さ上限／枝刈り）。実装は展開ノード予算 `maxNodes`（**q 評価 1 回ごとにリセット**、§7）で暴走を検出し、超過は黙って打ち切らず例外で通知する。
4. **`G` の事前計算可否**：`G` は陽に列挙せず、`T̂` 計算中に `q(S',V) ≥ P` を都度判定する遅延評価で十分（実装もそうしている）。
5. **配り手の評価指標（§6.5）**：相手盤面の「連鎖準備度の上昇」をどの式で測るか。
6. **外生モデル `R(C)`（解消済み）**：当初「最後の大きな未定義点」としていたが、`T̂` を**期待ターン数ヒューリスティック**にしたことで「山札の色分布からのドロー率 `2·d_c`」に単純化して解消した。相手手・未来の場ペア・被プレゼントは読まない。理由は実測で確認した次の 2 点：(a) 全状態の厳密値反復は状態数 ~10^17 で計算不能、(b) 順番を捨てる抽象化は連鎖の順序依存からゲームロジック上無意味（§6.1）。
7. **近似改良**：`T̂` は §6.1 の真値 `T*`（i.i.d. 2 枚モデルの SSP 最適期待到達ターン数。V=20 では全状態で有限）の近似。**小盤面（少色・浅 `K`・小 `V`）では `T*` を値反復で厳密に解ける**（`ai/scripts/_tstar-bench.ts`）ので、誤差を測りながら改良する。
   - 済: **改良A**＝「どれか早い色で到達」`E[min_c τ_c]`（単色 min の置換）、**改良C**＝過剰構築の抑制（最小枚数で停止）。これで小盤面の平均絶対誤差 1.84→0.15・相関 0.66→0.85。
   - 済: **二段構え**（§6.2）＝近距離のみ深さ 1 の後退帰納で混在色・両積み順を厳密展開。旧残差 +0.75 の主因（貪欲配置が最適でない／非単色の決定的連鎖を見ない）を解消し、**0.012・相関 0.99**。
   - 済（**非有望と結論・凍結**）: 教師あり学習（`T*` を厳密ラベルに色/スロット対称特徴でリッジ回帰・MLP、`ai/scripts/_grm-ml-*.ts`）。同一インスタンス内では残差回帰が改善するが、**色数をまたぐ汎化が無く**、ヒューリスティック自体の方が良く汎化する（詳細 `ai/CHANGELOG.md`）。
   - 残: **実戦勝率の測定と P 掃引**（旧プローブはノード予算バグで無効＝`ai/CHANGELOG.md`）。強さの最終物差しは現状最強（Gen-15: tempoChainAI、従来 tempoFast を有意勝ち）との対戦勝率。
